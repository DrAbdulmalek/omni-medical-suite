# SECURITY — قواعد الخط الإلزامية (PLANNED)

## لماذا GPG إلزامي؟
GitHub (ولو خاص) = طرف ثالث. قصاصات الخط اليدوي الطبي **بيانات حساسة**؛
التشفير قبل الرفع يجعل التسرب/الاستضافة بلا قيمة. القاعدة: **لا明文 يغادر VPS أبدًا.**

## المفاتيح
1. GPG keypair (Ed25519/Curve25519 موصى به) — **يُولَّد وقت التنفيذ V-6 بيد المالك، لا الآن** (قاعدة: لا توليد credentials في مرحلة التوثيق).
2. المفتاح **الخاص**: جهاز المالك فقط (+ نسخة باردة) — لا VPS، لا Colab disk، لا Git.
3. المفتاح **العام**: على VPS (للتشفير فقط) — لا خطر منه.
4. Colab: المفتاح الخاص/passphrase كـ**Colab Secret** يُحقن وقت التشغيل في الذاكرة؛ بديل آمن: symmetric passphrase كSecret.
5. **تدوير**: سنويًا، أو فورًا عند أي شك تسرب (سابقة توكن ATR تُدرَّس هنا).

## السلامة
- **SHA256** لكل artifact (dataset/model) في manifests — تحقق إلزامي قبل الاستخدام.
- **أصغر صلاحيات**: PAT/gh على VPS = contents:write لمستودع datasets فقط؛ Colab token = releases:write لمستودع models فقط.
- **لا PHI في logs**: notebook لا يطبع نصوصًا طبية؛ metrics فقط.
- **Rollback عند الفشل**: أي mismatch/عتبة → رفض + إبقاء السابق + إشعار.
- **بيانات التدريب الأولى**: اصطناعية حتى اعتماد corpus حقيقي وفق
  [../vps/PRIVACY_COMPLIANCE.md](../vps/PRIVACY_COMPLIANCE.md) (+ استشارة قانونية).

## ما لا يفعله هذا الخط (حدود صريحة)
- لا إخفاء هوية تلقائيًا (يُفترض أن المدخلات مفلترة مسبقًا).
- لا key management متقدم (HSM/Vault) — مستوى "مفاتيح ملفات" موثق المخاطر (R5).
